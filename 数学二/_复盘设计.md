# 复盘系统设计（302 数学二）

> 结论先行：**复盘不发奖励。** 它唯一的产出是「可信度」——也就是分数。
> 系统不锁任何东西，它只是**拒绝给你一个假的数字**。

---

## 一、为什么原来的复盘一定没人做

不是「用户懒」，是三个代码级事实：

| 位置 | 事实 | 后果 | 现状 |
|---|---|---|---|
| `store.js` `recordAnswer` | `if (correct) state.wrong[qid].resolved = true` | 错题答对**一次**就自动销账。没有间隔，「当时懂了」和「明天还记得」没被区分。 | ✅ 已删掉，改为两段验证 |
| `app.js` `retryQuestions()` | 把错题**原题**重开 | 人最讨厌「这题我做过了」——**重复就是惩罚**。 | ✅ 回炉间出的是**同类变式** |
| 面板 Tab | 错题本是一份**无尽清单** | 没有开始、没有终点、没有演出 → 天生拖延。 | ✅ 回炉间有一局、进度条、结算屏 |

**额外发现（关键资产）：** `optionNotes` 不是普通干扰项点评，它逐选项写了「谁会选它、为什么」——
例如 `lf-1` 的 B 项：「量词顺序被颠倒……**只记住「有两个正数」而没记清谁控制谁**的同学最容易选它。」
这就是一份现成的复盘诊断稿，之前只在答错后展示一次就没了。

## 二、三条支柱（用户确认）

| 支柱 | 落点 |
|---|---|
| **分数**：我能考多少分 | 考场预测面板：把掌握度按真题分值占比折算成 150 分制 |
| **不打折的「我会了」** | 信任度分四档；没验过的掌握只算「待验证」，差额即「虚分」 |
| **推进惯性：别停** | 复盘做成**入口闸机**（打开系统先过 2–3 题），不是卡在关卡中间 |

**已否决：卡奖励口**（宝箱 / 回炉石 / 收集品）。用户原话：「我对这个奖励根本就不上心。」
→ 结论：不做游戏经济，做**诊断仪表**。

## 三、信任度模型（已实现，`store.js`）

| 状态 | 条件 | 可信上限 cap | 含义 |
|---|---|---|---|
| `blank` 空白 | 没练过 | 0 | 不计入任何分 |
| `half` 未通关 | 练过但没通关 | 0.5 | 只算半信 |
| `claimed` 待验证 | 通关了，但没在真题里验过（或错题未清） | 0.7 | 练习正确率再高也不能当成会 |
| `verified` 已坐实 | 通关 + 真题通 + 错题清 | 1.0 | 认账 |

**考场预测**（`weight` 合计 300 ↔ 150 分制，即 1 weight = 0.5 分）：

```
预计得分 = 0.5 × Σ(weight_n × min(实测正确率_n, cap_n))
纸面得分 = 0.5 × Σ(weight_n × 实测正确率_n)        ← 「你以为拿到」的分
虚    分 = 纸面 − 预计                              ← 考场上真会丢的分
```

参数集中在 `TRUST_CAP`，想收紧/放松只改一处。**纯读取，不写存档**：
通关数 / 七龙珠 / 掌握度热力图 / 成就全都不受影响。

### 当前真实数据（2026-10 存档）

```
预计 7.4 / 150      纸面 9.7      虚分 2.3（占纸面 24%）
已覆盖 10.5 分（4 / 69 考点）      还没碰 139.5 分
4 个考点全部「待验证」：练通了，但一个真题都没做
```

→ 这句话就是整套系统的强制力：**「你以为拿到 9.7 分，其实只有 7.4 分是真的。」**

## 四、强制从哪来（都不靠奖励）

1. **结论口**：未验证的考点，地图/简报**不显示「已掌握」**，显示「待验证」；掌握度环的绿是「假绿」。
   —— 系统拒绝替你撒谎。（待做：地图视觉）
2. **分数账本**：虚分是一个**一直挂着的数字**，不会因为你不管它就消失。（已做：HUD + 统计面板）
3. **入口闸机**：打开系统 → 先过 2–3 题今日回炉（3 分钟，永远做得完）→ 才进地图。
   —— 不是墙，是闸机；墙让人放弃，闸机让人顺手过一下。（待做）

## 五、复盘动作 = 回炉间 ✅ 已实现

入口：右上角 **🔥 回炉间**（徽标 = 今天可验几道）；错题本里也能单题回炉。
一局默认 8 道（约 3–5 分钟），三道屏（`js/huilu.js`）：

1. **① 诊断屏**（不给做题，只认账）：
   原题 + 「你当时选了 B」+ `optionNotes[picked]` 的精准诊断 + 正确答案及其说明
   + 一行「师傅：这个考点记住一句话 —— `node.points[0]`」。
   → **诊断文案不用 AI**，全部来自题库里已有的 `optionNotes`（它本来就是给干扰项写的复盘稿）。
2. **② 变形屏**：出 `variants[i].stem`（同类变式，**不是原题**），自己先做 → 看解析 → 诚实自评。
   变式只有 `{stem, hint}`、**没有选项和答案**，所以这一步天然只能自评 —— 与解答题「看解析自评」同一套约定。
   该题没有变式时**如实标注**「暂无同类变式 → 原题重做」，不假装。
3. **③ 归位屏**：段位前进 / 被间隔挡住 / 连错撤下，各有各的话术；最后一题后是**结算屏**
   （本局几道、出炉几道、待验几道、考场预计与虚分，并写明「复盘不发奖励」）。

**键盘**：`空格/Enter` 主操作、`1` 答对、`2` 没答对、`Esc` 退出。

### 数据模型（`state.wrong[qid]` 从布尔升级成段位）

```js
{ node, ts, times,          // 已有
  picked: 1,                // ★新增：当时选了什么（诊断屏全靠它）
  stage: 0,                 // 0 新错 → 1 变式答对 → 2 隔天再答对 = 出炉
  due: 1792280000000,       // ★新增：下次可回炉的时间（真·隔天）
  usedVariants: [0, 1],     // ★新增：用过哪些变式，避免重复
  fails: 0,                 // 本轮连错次数
  stuck: false }            // 连错 2 次 → 从自动队列撤下，交给师傅讲
```

**间隔**：第二段必须跨过**凌晨 4 点**（熬夜党凌晨 3 点回炉不会被算成没过一天）。
**答错**：段位不倒退，只累计 `fails`；到 2 次就撤出自动队列（防挫败堆积），答对即重新入队。
**重要**：`recordAnswer` 已**不再**「答对一次就销账」——「练」不等于「验」，唯一的自动出口是回炉两段；
错题本里保留「🧹 全部消化」作为手动逃生门。

### 校验

- `node _test-huilu.js` → 30 项断言全过：分段推进、真·隔天拦截、当天硬来不给进度、
  出炉后 `trust` 从 `claimed` 变 `verified` 且虚分归零、连错 2 次撤下、旧档缺字段按新错处理。
- 浏览器端跑通了完整一局（3 道 × 三屏 + 结算屏），0 console error；测试后存档已按字节还原。

## 六、内容：「自动换数字」的真实成本

775 道题里只有 **389 道自带 `variants`**，其余需要生成。必须诚实说明：

- **这不是正则能做的。** 换数字后答案也跟着变，只能**离线逐题生成 + 交叉验算**，
  写进 `data-q-*.js` 的 `variants: [{stem, hint}]`（沿用现有约定，hint 里带答案/思路）。
- **铁律：生成错的变式比没有变式更糟。** 考研数学二靠这个提分，答案错了会直接教坏人。
  → 选择题必须保证新正确项唯一最优；填空题必须重新算出答案并补进可接受写法；
  **解答题 / 证明题不要换数字**，改结构性变式或降级为「看解析复述」自评。
- 优先补**高频易错**的题，不追求 100% 覆盖。

## 八、已知取舍（都是明知故犯）

- **v1 的「验」有两层**：真题关（`ztCleared`）+ 错题出炉。真题那层零新代码，
  代价是部分考点只有 1–2 道真题，粒度很粗（`gs-lim-fn` 只有 1 题）。真正的「验」是回炉间，
  等变式补齐后可以把 `verified` 的判定收紧到「只认回炉出炉」。
- **变式不可自动判分**：`variants` 只有 `{stem, hint}`，没有选项和答案 → 变形屏只能**诚实自评**。
  这和解答题的「看解析自评」是同一套约定，没有引入新的作弊面。
- **386 / 775 道题还没有变式** → 那些题的回炉会显示「原题重做」并如实标注。
  宁可承认「这题暂时只能用原题」，也不假装出的是变式。
- **每题通常只有 1 个变式** → 第二段会重复同一道变式（`usedVariants` 用完后从头再来）。
  变式补到 2 个以上才谈得上「不重复」。
- **答错不倒退段位**，只累计 `fails`：SM-2 那种「错一次回到解放前」对刷题信心伤害太大。
- **未覆盖按 0 计**：预测会低估（课堂上学过的没算进去）。面板上已注明「按本系统已覆盖内容估算」，
  并单独列出「还没碰 139.5 分」，避免数字被误读成实力。
- 真题正确率**不参与**折算：单考点真题只有 1–2 题，比率噪声太大（0% 或 100%），会把预测打乱。
  等题量上来再考虑混合。
